# Analytics Plugin

**Upstream docs (always check for latest):** https://databricks.github.io/appkit/docs/plugins/analytics
Also consult the live AppKit docs: `npx @databricks/appkit docs "analytics"`
The information below may be outdated. Prefer upstream when available.

> **Client routing:** commands below are for the **IDE/CLI** path. On **Genie Code**: add packages to `package.json` instead of `npm install` (platform installs server-side on deploy); run `databricks …` via `runDatabricksCli` and **omit `--profile`**; `npx … docs` → WebFetch the docs site. See the routing table in [`../SKILL.md`](../SKILL.md) and `skills/genie-code-environment`.

SQL query execution against Databricks SQL Warehouses with file-based queries, automatic type generation, and built-in caching.

**Capabilities:** File-based SQL queries, parameterized queries with type-safe helpers, JSON and Arrow format support, caching, retry logic, SSE streaming.

## Adding to an Existing AppKit Project

### 1. Register the Plugin

In `server/server.ts`:

```typescript
import { analytics, createApp, server } from "@databricks/appkit";

await createApp({
  plugins: [server(), analytics({})],
});
```

### 2. Environment Variables

You need a SQL Warehouse ID. Discover it with:

```bash
databricks aitools tools get-default-warehouse --profile <PROFILE>
# fallback if aitools is unavailable: databricks warehouses list --output json | jq -r '.[0].id'
```

Add to `.env`:

```env
DATABRICKS_SQL_WAREHOUSE_ID=<warehouse-id>
```

Add to `app.yaml`:

```yaml
env:
  - name: DATABRICKS_SQL_WAREHOUSE_ID
    valueFrom: sql-warehouse
```

### 3. Create SQL Query Files

Put `.sql` files in `config/queries/`. The filename without `.sql` becomes the query key.

```sql
-- config/queries/spend_summary.sql
-- @param startDate DATE
-- @param endDate DATE
SELECT department, SUM(amount) as total
FROM catalog.schema.expenses
WHERE expense_date BETWEEN :startDate AND :endDate
GROUP BY department
ORDER BY total DESC
```

**Execution context by filename:**
- `queryKey.sql` — executes as service principal (shared cache)
- `queryKey.obo.sql` — executes as user (on-behalf-of, per-user cache)

**Supported `@param` types:** `STRING`, `NUMERIC`, `BOOLEAN`, `DATE`, `TIMESTAMP`, `BINARY`

**Server-injected parameters:** `:workspaceId` is injected automatically — do NOT annotate it.

### 4. Generate Types

```bash
npm run typegen
```

This creates `client/src/appKitTypes.d.ts` with TypeScript types for all queries.

### 5. Frontend Usage

```typescript
import { useAnalyticsQuery } from "@databricks/appkit-ui/react";
import { sql } from "@databricks/appkit-ui/js";

function SpendTable() {
  const params = useMemo(() => ({
    startDate: sql.date("2025-01-01"),
    endDate: sql.date("2025-12-31"),
  }), []);

  const { data, loading, error } = useAnalyticsQuery("spend_summary", params);

  if (loading) return <Skeleton className="h-32 w-full" />;
  if (error) return <div className="text-destructive">{error}</div>;
  if (!data?.length) return <div className="text-muted-foreground">No results</div>;

  return (
    <ul>
      {data.map((row) => (
        <li key={row.id}>{row.name}: ${row.cost_usd}</li>
      ))}
    </ul>
  );
}
```

### Type-Safe Queries

Augment the `QueryRegistry` interface for full type inference:

```typescript
// config/appKitTypes.d.ts (auto-generated by npm run typegen)
declare module "@databricks/appkit-ui/react" {
  interface QueryRegistry {
    spend_summary: {
      name: "spend_summary";
      parameters: { startDate: string; endDate: string };
      result: Array<{ department: string; total: number }>;
    };
  }
}
```

## Gotchas

- **Always wrap parameters in `useMemo`** to prevent infinite refetch loops. The hook re-executes when the parameters reference changes.
- **Run `npm run typegen` before writing UI code** — types won't exist until generated.
- **Format options:** `"JSON"` (default) returns JSON rows; `"ARROW"` returns Arrow via SSE then binary fetch.

## HTTP Endpoints

- `POST /api/analytics/query/:query_key` — execute a query
- `GET /api/analytics/arrow-result/:jobId` — fetch Arrow binary result
