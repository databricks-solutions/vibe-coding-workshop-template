# Workspace Instructions — Vibe-Coding Workshop

## Error Handling — MANDATORY

**On ANY error during the AppKit workshop, STOP and read `apps_lakebase/gc-prompt-conversion/troubleshooting_gc.md` FIRST.**

This file contains the complete error-to-fix lookup tables for all 5 workshop steps, pre-deploy checklists, post-deploy verification steps, and correct SDK patterns. Match the error message or symptom in the tables and apply the fix exactly as described. Do NOT improvise a workaround or hallucinate a fix before consulting this reference.

Common categories covered: SDK bootstrap, SDK file operations (base64 encoding, mkdirs, unicode in JSX), scaffold/build errors, deploy failures, Lakebase provisioning, resource binding types, plugin order, API route registration, and runtime debugging.

## Genie Code Behavior Rules

### Apps

When asked to build or modify an app, **prefer AppKit** — use the `@appkit-apps`
skill and the scaffolding patterns in `apps_lakebase/skills/`. Do not generate
raw FastAPI, Express, or pg-based apps from scratch. AppKit provides the correct
plugin architecture (`analytics()`, `lakebase()`, `genie()`, `server()`) and
handles Databricks auth, app.yaml, and deployment automatically.

If AppKit is explicitly inappropriate (e.g., the user needs a non-TypeScript
stack), say so and explain the tradeoff before proceeding with raw code.

### Data Products

When asked to build data products, **follow the 9-stage accelerator** and use
`SKILL.md` files in `data_product_accelerator/skills/` as primary guidance:

1. Gold Design → 2. Bronze → 3. Silver → 4. Gold Impl → 5. Planning →
6. Semantic Layer → 7. Observability → 8. ML → 9. GenAI Agents

Read `@data-product-accelerator` for the full skill map. Match the user's
keywords to the correct stage before writing any code. Start at Stage 1 for
new projects; jump to the relevant stage for incremental work.

### Agents

When asked about agents, **reuse patterns in `agentic-framework/` first** —
the 8 agent prompts and the Foundation Model agent-loop skill contain
battle-tested patterns for PRD analysis, tool building, multi-agent
orchestration, and deployment. Read `@agentic-framework` for the full pipeline.

Do not build agent loops from scratch when the `foundation-model-agent-loop`
skill already provides the correct Databricks Foundation Model tool-calling
pattern with structured output parsing.

## Agent Memories

### Databricks Apps Build Environment (verified 2026-07-24)

- `npm` v10.9.2 and `node` v22.16.0 are available; **`npx` is NOT in PATH**
- **`@databricks/appkit` is a CLI-only tool** with commands: `setup`, `generate-types`, `lint`, `docs`, `plugin` — it has **no `build` or `start` commands**
- Default scaffolds (templates or copied snippets) often ship `package.json` / `app.yaml` with `npx @databricks/appkit <cmd>` — these MUST be overwritten per `GENIE-CODE-OVERRIDES.md`
- Correct build script: `"build": "npm run typegen && vite build"` with `"typegen": "npm exec @databricks/appkit -- generate-types"` (not bare `vite build` — typegen generates Lakebase types and prevents build failures when Lakebase is wired in later)
- Correct start: `"start": "tsx app.ts"` with `tsx` as a dependency; `app.yaml` command: `["./node_modules/.bin/tsx", "app.ts"]`
- Vite config needs `root: "client"` (where `index.html` lives) and `outDir: "../dist"` (AppKit's `server()` serves from `dist/`)
- `client/index.html` is mandatory for vite build — without it: `Could not resolve entry module "index.html"`
- `app.ts` must only include `server()` plugin when no resources are configured — `analytics()`, `genie()`, `lakebase()`, `files()` crash at runtime without their respective env vars/resources
- `server/server.ts` must export `registerRoutes(appkit)` using `appkit.server.extend((app) => {...})` — NOT `server.extend((app, ctx))` or `createApp()`
- `app.ts` with Lakebase must use `onPluginsReady` pattern: `createApp({plugins:[lakebase(), server()], async onPluginsReady(appkit){await registerRoutes(appkit)}})` — NO `export default`, NO `autoStart: false`, NO `.then()`, NO `appkit.server.start()`, NO top-level `await` (CJS constraint)
- Lakebase queries use `appkit.lakebase.query(sql, params)` — NOT `ctx.lakebase.getPool()` or `createLakebasePool()`
- Health endpoint returns `{ data: [{ status: "connected" }], source: "live" }` — wrapped in `data` array for `useLakebaseData` hook compatibility
- **Deploy path (SDP only):** Use `validate_and_deploy()` from `apps_lakebase/gc-prompt-conversion/workshop-variables.md` — SDK **`sdk_preflight_app_folder`** plus **`w.apps.*`** (`create_and_wait`, `deploy_and_wait`). **No** Databricks Jobs and **no** `_deploy_app` notebook for deployment.
- Product name: **StayFindr** (not VacaVista — the repo standard is StayFindr throughout)
- Lakebase projects/databases: create via **SDK** (`w.database` / `w.postgres`) per `setup_lakebase_gc.md` and `04-appkit-plugin-add` skill — then merge `package.json` / `app.yaml` with `write_file()`.

### Deploy Rules (verified 2026-07-24)

- **Preflight:** `validate_and_deploy()` runs **`sdk_preflight_app_folder(APP_BASE)`** — catches missing `app.yaml`, core paths, etc., before deploy.
- **App SP + workspace path:** The **Databricks App’s service principal** must be able to **read** `APP_BASE` during the platform build. Grant **`CAN_READ`** on the workspace folder (and **`CAN_MANAGE`** on the app as required) using `service_principal_client_id` from `w.apps.get(APP_NAME)` (UUID). See `apps_lakebase/skills/01-appkit-scaffold/SKILL.md` Step 5 for grant patterns.
- **Primary method (Genie / workshop helpers):** Use **`validate_and_deploy(APP_NAME, APP_BASE)`** from `apps_lakebase/gc-prompt-conversion/workshop-variables.md` — SDK preflight, then `create_and_wait` (if missing), `ensure_app_active`, and `deploy_and_wait` with `AppDeployment(source_code_path=APP_BASE)`. Do not hand-roll that sequence in prompts; the helper is the contract (see `gc-prompt-header.md`). **No Jobs.**
- **Optional — MCP-only environments:** If you still use `appkit_validate` / `appkit_deploy`, grant the **MCP SP** `CAN_READ` / `CAN_MANAGE` as in `MCP-appkit_tooling.md` — not required for the standard SDK workshop.
- **`App` object quirk:** Use `app.compute_status.state` (not `app.status`) — the `App` object has no top-level `.status` attribute
- **`.state.name` for string comparison:** Use `app.compute_status.state.name` to get `"ACTIVE"` — `str(state)` returns `"ComputeState.ACTIVE"` which breaks `== "ACTIVE"` comparisons and causes infinite polling loops
- **Common deploy failure:** `error: unknown command 'build'` → means `package.json` still has `appkit build` instead of `npm run typegen && vite build`

### SDK / Genie bootstrap (verified 2026-07-24)

- **Kernel restart recommended** after `%pip install databricks-sdk --upgrade` if you hit import issues.
- **MCP (`databricks-mcp`, `nest_asyncio`, `DatabricksMCPClient`):** optional only — standard workshop uses `workshop-variables.md` Cell 1–3 without MCP.
- SDK file writes must use `format=ImportFormat.AUTO` (the enum from `databricks.sdk.service.workspace`), not the string `"AUTO"`
- **`service_principal_client_id` vs `service_principal_id`:** Permissions APIs and Lakebase role grants (`w.database.create_database_instance_role`) require the UUID (`app_info.service_principal_client_id`), NOT the numeric `service_principal_id`. Using the wrong one gives "Identity not found" errors
- **Lakebase resource type:** AppKit's `lakebase()` plugin requires a `postgres`-type resource (`AppResourcePostgres`), NOT a `database`-type resource (`AppResourceDatabase`). Using the wrong type causes `ConfigurationError: Missing required resources: postgres:Postgres [lakebase]` at startup. Discover database paths via `w.postgres.list_databases(parent=f"projects/{APP_NAME}/branches/production")`
